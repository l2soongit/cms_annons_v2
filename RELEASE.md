# Чекліст запуску graj.club

Як встановити й оновлювати сайт, описано в [DEPLOY.md](DEPLOY.md). Тут — що зробити й перевірити, щоб запуск пройшов без сюрпризів.

Усе, що можна перевірити автоматично, перевіряє одна команда на робочому сервері:

```
php artisan release:check
```

✗ — блокує запуск, ! — бажано виправити до бети, ✓ — гаразд. Запускати можна, коли немає жодного ✗.

## 1. Хостинг і домен (за тиждень до запуску)

- [ ] Хостинг відповідає вимогам із DEPLOY.md. Хостер письмово підтвердив, що дозволені вихідні UDP/TCP-з'єднання: без них моніторинг покаже всі сервери офлайн
- [ ] Домен `graj.club` вказує на хостинг, SSL-сертифікат видано (Let's Encrypt у панелі)
- [ ] Якщо використовується Cloudflare: проксі ввімкнено, режим SSL — Full (strict)
- [ ] `http://` і `www.` переадресовують на `https://graj.club`
- [ ] Для пошти домену налаштовано SPF, DKIM і DMARC, інакше листи підтвердження потраплятимуть у спам

## 2. Ключі й сервіси

Де взяти кожен ключ, описано в DEPLOY.md → «Зовнішні сервіси».

- [ ] `.env` заповнено з `.env.production.example`, `APP_DEBUG=false`
- [ ] SMTP: тестовий лист реєстрації дійшов на Gmail і на ukr.net
- [ ] LiqPay: бойові ключі, `LIQPAY_SANDBOX=false`
- [ ] Stripe: бойовий обмежений ключ (`rk_live_…`), вебхук на `https://graj.club/api/billing/callback/stripe` з чотирма подіями, `whsec_…` у `.env`
- [ ] Turnstile, IPQS, Sentry
- [ ] Google і Discord: redirect-адреси вказують на `https://graj.club/...`
- [ ] Telegram: вебхук зареєстровано (посилання в DEPLOY.md), `/start` у боті відповідає
- [ ] Сховище для бекапів (SFTP): доступ є, `BACKUP_SFTP_*` у `.env`, `php artisan db:backup` завантажив копію

## 3. Встановлення

- [ ] Кроки «Перше встановлення» з DEPLOY.md виконано, cron додано
- [ ] Перший адміністратор: `php artisan user:make-admin you@graj.club` (пароль питається приховано). Під час першого входу в `/admin` налаштовано 2FA
- [ ] Модераторам видано роль в адмінці («Користувачі»), у кожного налаштовано 2FA
- [ ] `php artisan release:check` — жодного ✗

## 4. Наповнення

- [ ] Ігри: активні ігри, поля й фільтри, порядок, обкладинки, SEO-тексти сторінок ігор (адмінка → «Ігри»)
- [ ] Головна: тексти першого екрана, швидкі запити, видимі блоки (адмінка → «Головна сторінка»)
- [ ] Сторінки: правила, FAQ, контакти. Політику конфіденційності перевірив юрист
- [ ] Англійська версія: переклади ігор, сторінок і інтерфейсу (адмінка → «Переклади»), `/en` виглядає завершеним
- [ ] Тарифи й ціни: VIP, підняття, оголошення, банери. Ціни узгоджено
- [ ] Демо-серверів немає (у production вони не створюються; `release:check` перевіряє це, якщо базу переносили)
- [ ] 5–10 справжніх серверів додано заздалегідь, щоб у перших відвідувачів не було порожніх списків

## 5. Закрита бета (1–2 тижні)

Сайт працює на робочому домені. Запросіть 10–20 власників серверів з різних ігор і дайте їм прямий контакт для відгуків (тікети підтримки).

Перевіряємо на живих даних:

- [ ] Власник сам додає сервер, модерація схвалює його протягом доби
- [ ] Онлайн і статус з моніторингу збігаються з тим, що бачить власник
- [ ] Callback голосування доходить на сервер, гравець отримує бонус
- [ ] Справжня оплата на мінімальну суму через LiqPay і Stripe: послуга активується, сума в історії правильна
- [ ] Банер купується, показується й знімається після терміну
- [ ] Повідомлення, тікети, Telegram- і Discord-сповіщення доходять
- [ ] Сайт перевірено на телефоні (Android і iPhone)
- [ ] У Sentry немає нових помилок, `release:check` без збоїв черги

Критерій завершення бети: два тижні без критичних помилок, усі пункти вище виконано.

## 6. День запуску

- [ ] Свіжий бекап: `php artisan db:backup`
- [ ] `robots.txt` відкритий для індексації (у production — автоматично), `https://graj.club/sitemap.xml` відкривається
- [ ] Сайт додано в Google Search Console і Bing Webmaster Tools, sitemap надіслано
- [ ] Оголошення для власників серверів і гравців

## 7. Після запуску

Щодня перші два тижні, далі щотижня:

- [ ] Sentry: нові помилки
- [ ] `php artisan release:check`: cron, черга, свіжий бекап
- [ ] Черга модерації в адмінці

Щомісяця:

- [ ] Пробне відновлення бекапу в окрему базу (див. нижче)
- [ ] `composer audit` і `npm audit` (запускаються в CI на кожному пуші)

## Відновлення з бекапу

Бекапи лежать у `storage/app/private/backups` і в SFTP-сховищі: `db-РРРР-ММ-ДД-ГГХХСС.sql.gz`, по одному на день за останні 14 днів.

1. `php artisan down`
2. Відновлення бази (замінює всі таблиці):
   - через SSH: `gunzip < db-….sql.gz | mysql -u КОРИСТУВАЧ -p НАЗВА_БАЗИ`
   - без SSH: phpMyAdmin → «Імпорт» → файл `.sql.gz` (стиснені файли phpMyAdmin приймає)
3. Якщо разом із базою відкочується код: GitHub → Actions → «Deploy to hosting» на потрібному коміті
4. `php artisan migrate --force && php artisan optimize`
5. `php artisan up`

Пробне відновлення робіть в окрему порожню базу, а не в робочу.
